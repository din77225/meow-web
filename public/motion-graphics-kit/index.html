What you need

Required

Claude desktop app

Use the Code tab, not the regular chat, and pick Opus 5.5 or a newer model. Works on any paid Claude plan. On a Team or Enterprise plan, an owner may need to allow the OpenArt connector first.

claude.com/download
Required

The Remotion plugin

In Claude Code, go to Customize, Plugins, search "remotion" and hit Add. (In the video I went through Settings, same thing.) Remotion is what turns the code into a video.

For the images

An OpenArt account

This is where I make the images, Extract Layers and the voiceover in the video, on OpenArt. Connect it to Claude and it pulls the files in for you. Already have your own images and clips? Those work too. OpenArt's video on connecting OpenArt to Claude.

Set up once, about 10 minutes

Three steps, then you just talk to Claude

Download the kit

Download the kit (ZIP, 7 MB)

Make a project folder

Make a new empty folder, for example my-motion-studio. Open it in the Code tab and allow access. Pick Accept edits so Claude doesn't ask before every file.

Accept edits lets Claude create and change files in this folder without asking each time. It still asks before running other commands. Have a quick read of what each mode allows: Claude's guide to permission modes.

Paste the setup prompt

It installs what's missing, unpacks the kit, builds your folders and rules, and renders a 3 second test, so you know it all works.

Read the setup prompt
Set up a motion graphics workspace for me in this folder. I'm a beginner, so before each step tell me in one short sentence what you're doing and why. Ask me before you install anything outside this folder.

1. Check which computer I'm on. Check that Node.js 20.19 or newer is installed (node -v). If it isn't, install the current LTS version for me: on Windows with winget (winget install OpenJS.NodeJS.LTS), on a Mac with Homebrew if I have it, otherwise the official LTS installer from https://nodejs.org/en/download. On Windows, also check Git for Windows (git --version) and install it if it's missing (winget install Git.Git). On a Mac, check the Xcode Command Line Tools (xcode-select -p) and if they're missing, run xcode-select --install and tell me to click Install in the window that pops up (the local Whisper needs them). Tell me before each install. If an install needs my password, give me the exact command to paste into the Terminal app myself, because you can't type it for me. If an install needs a new terminal, tell me to reopen Claude Code, then check again.

2. Create a Remotion project in this folder with the official starter: npx create-video@latest --yes --blank . (if the folder isn't empty, scaffold into a temporary subfolder, move everything up, and set the name in package.json to this folder's name). In remotion.config.ts, set Config.setOverwriteOutput(false) so a render never replaces an older one. Check that the Remotion plugin is active. If it isn't, run: npx remotion skills add

3. Find the kit I downloaded: look in my Downloads folder for mia-motion-graphics-kit (it may have a number added, or already be unzipped). If there are several, show me their names and dates so I can choose. If you can't reach Downloads, tell me how to give you access, or I'll move the ZIP into this folder. Unzip it here without overwriting anything. You should now see mia-motion-graphics/ (the skill), templates/ (10 styles) and KIT-README.md.

4. Make these folders: inputs (my images, layers and clips), references (style images and videos I like), audio (voice, music, sound effects), renders (finished videos), notes, notes/frames. Then show me the whole folder as a simple tree.

5. Create CLAUDE.md with these working rules and follow them in every chat here:
   - Read mia-motion-graphics/SKILL.md before any motion graphics work.
   - Before building, ask me what it's for, the format and length, the exact words, the feeling, and whether there's sound.
   - Suggest one to three templates from templates/ that fit, with a one-line reason each. Reuse their build notes and specs instead of starting from scratch.
   - From a style reference, take its grammar (type, colours, pacing, how text enters and exits), never its content, logos or characters. Rebuild everything in code.
   - Plan the video second by second, then show me three still frames before rendering the full video.
   - Keep all words, colours, fonts and timings in one config file, so a headline change is one line.
   - Copy files into public/ before using them. Never move or edit my originals.
   - When I give you a video, give yourself eyes and ears first. Eyes: make a folder notes/frames/<clip name>/ and pull frames into it with npx remotion ffmpeg -i <video> -r 2 notes/frames/<clip name>/f_%03d.jpg, then look at them. Ears: if it has sound, pull the audio (npx remotion ffmpeg -i <video> -vn -ac 1 -ar 16000 notes/frames/<clip name>/audio.wav) and transcribe it with Remotion's local Whisper (@remotion/install-whisper-cpp) with word timestamps. Never ask me to install FFmpeg.
   - If I make images, layers or voiceovers on OpenArt, pull them through the OpenArt connector into inputs/ or audio/ when I say they're ready. Otherwise I'll drop files there myself.
   - Never overwrite a render. Save v2, v3 and so on.
   - After every render, check frames from the whole video, score it out of 10 for layout, timing, readability and polish, fix anything under 8, and tell me what's wrong before you say it's done.
   - If I ask for an overlay to use in CapCut, Premiere or DaVinci, render it with a transparent background: --codec=prores --prores-profile=4444 --pixel-format=yuva444p10le --image-format=png, as a .mov.
   - For vertical videos made for Reels, TikTok or Shorts, keep words and key visuals out of the bottom fifth and the right edge, where the app's buttons and caption sit.
   - If you add sound, aim for about -14 LUFS so it isn't quieter or louder than other videos in the feed.
   - In captions, use my exact words. If you're not sure what I said, ask me instead of guessing.
   - When I correct something, add it to notes/checks.md as a DO or DON'T line and read that file before every render.
   - Never generate paid images, video or audio without asking me first.

6. Ask me if I want to connect OpenArt (optional). If yes, walk me through it: Customize, Connectors, add a custom connector named OpenArt with the URL https://mcp.openart.ai/mcp, then Connect and sign in (no API key needed). Test it by listing my recent OpenArt creations.

7. Make a 3 second test video that says "Ready" on a pink background and render it to renders/test.mp4. Test your eyes: pull one frame from it and tell me what you see. Test your ears: set up the local Whisper with whisper.cpp version 1.5.5 (ask me before downloading the model, the base English one is enough) and transcribe mia-motion-graphics/sample-voice.wav, then show me the words with their timings. Then start the preview (npm run dev) in the background so it doesn't block you, and give me the link to Remotion Studio.

If the test render times out, try again and point Remotion at my system Chrome with --browser-executable. When you're done, tell me in a few lines what's set up and what to try first.

Your first try

Put any picture in your inputs folder, then paste something like this. Just say in plain words what you want to see:

Here's my image: inputs/[FILE NAME]. Add motion graphics and the headline LIGHTEN UP. 6 seconds, 1080 by 1350. Airy and playful. Ask me questions before you build anything.

👀 Eyes

Claude can see images but can't play a video. So for any clip you give it, it pulls frames (two per second) with Remotion's built-in FFmpeg and looks at them first. That's how it knows when the product turns, when a cut happens, and where a label can go without covering a face. You never install FFmpeg yourself.

👂 Ears

If the clip has sound, Claude pulls the audio and transcribes it with the local Whisper, word by word with timestamps. That's how a headline lands exactly on the word you say, and how it catches where the music hits when you show it a style you like.

Plain English

Skill, template, prompt: what's the difference?

Read the short explanation
The skill

My how I work rules: ask first, show three stills, build in code, check the render. Claude reads it every time, so you just ask for what you want, like "make my product photo move".

A template

In this kit, a template is one look: a preview, a short description of the style, build notes and known pitfalls. Pick one, and Claude rebuilds that look with your own pictures and words. It's not a fill-in file like a Canva or CapCut template.

A prompt

Anything you type to Claude is a prompt, and plain English works. In this kit, each template also comes with a ready-made prompt you can copy. Fill in the [brackets] with your files and words, or leave them and Claude will ask.

How to use it

Open your project folder in the Code tab and describe what you want in plain English. To pick a look, name a template ("use the Paper cut template") or paste its prompt from the library below. To fix something, give the time and what you see ("at 0:03 the headline covers her face, move it up").

The three workflows from the video

How I made each part

Short versions, step by step. Swap the [brackets] for your own files and words. If you don't use OpenArt, skip those steps and put your own files in inputs/.

1 · Image + motion

A picture that moves: the moving carousel (video 1:10)

  1. Make the image

    Talk through the product and the vibe first, then let Claude write the image prompt and make it with an image model on OpenArt (I used GPT Image 2.5). Any image of your own works too.

    I'm making an Instagram carousel for [PRODUCT]. Here's the product photo inputs/[FILE] and a photo of me inputs/[FILE]. The vibe: [VIBE]. Write an image prompt and make one 4:5 image on OpenArt (for example with GPT Image 2.5). Leave clear space for a headline. Show me the prompt before you generate.
  2. Split it into layers (optional)

    On OpenArt, open Image Tools, then Extract Layers. Upload the image, pick how many layers (I picked six), and save them. This is what lets text sit behind you. With the OpenArt connector, Claude can pull them in. Without it, download them into inputs/.

  3. Animate it

    Tell Claude how it should move. Ask it to rebuild the words in code, so you can change them later.

    My layers are saved on OpenArt: [LAYER NAMES]. Pull them in through the OpenArt connector (or use my files in inputs/). Make a 6 second slide, 1080 by 1350. Skip the text layer and rebuild the headline [WORDS] in code, as close to the original style and font as you can. Movement: [HOW IT SHOULD MOVE]. Ask me questions before you build anything.
  4. Change it anytime

    One line, no new image.

    Change the word behind me to [NEW WORD]. Then make a second version with the same image and layers but a new layout: [DESCRIBE IT].
2 · Graphics on an AI video

Labels and headlines on a product clip (video 4:09)

  1. Make a clean clip

    Keep it simple and ask for no text, so the video model has less to get right. I used Seedance 2.5 on OpenArt.

    Slow turn of [PRODUCT] on a soft [COLOUR] studio backdrop, then three gentle close-ups: [DETAIL 1], [DETAIL 2], [DETAIL 3]. Smooth camera, soft even light. No text, no logos, no words on screen.
  2. Decide the look first

    Pick the design before any motion. One clear frame becomes three style references.

    Pull one clear frame from inputs/[CLIP]. Use it as the base and make three style references with an image model on OpenArt (for example GPT Image 2.5): a fashion editorial, a game-style heads-up display, and a hand-drawn doodle. Keep the product exactly as it is.
  3. Build it

    Give Claude the clip and the still you like, plus a rough shot plan in plain words.

    Here's the clip inputs/[CLIP] and the style I like references/[STILL]. The clip is the base, the still is how the graphics should look. Rebuild every letter in code. Shot 1 shows [WHAT], shot 2 [WHAT], shot 3 [WHAT], shot 4 [WHAT]. Turn my words into short marketing copy, show me the shot plan, then build it.
  4. Test headlines

    Same footage, only the words change. See the A/B prompt below.

3 · Animated with code

The cozy cooking game, or a music video (video 6:32)

  1. Story and style first

    Describe a story and a look. Claude plans the scenes and works out which characters, poses and backgrounds the story actually needs. More actions, more poses.

    Here's my story: [STORY, e.g. a cat who can't cook and an AI helper, told like a cozy old Japanese RPG with text boxes and a mini game, or a music video for my song]. Length: [LENGTH]. Plan it scene by scene. Then list the characters, the poses each one needs for the actions in the story, and the backgrounds. Keep the number of poses as small as the story allows.
  2. Characters and backgrounds

    Claude makes the art from its own list with an image model on OpenArt (I made mine with GPT Image 2.5).
    No connector? Make them on OpenArt yourself and drop them into inputs/.

    Make the art from your list with an image model on OpenArt (for example GPT Image 2.5): one sheet per character with every pose you listed, on a plain flat background with space between the drawings, and each background as its own image. Show me the cost before you generate.
  3. Voices

    Make the voice lines with OpenArt's voiceover tool. If the OpenArt connector is set up, Claude can pull them in for you. If not, download them into audio/.

  4. Animate it

    The look is cut-out animation: drawings cut from the sheets, moved over painted backgrounds. It's the same style for a game, a music video or any story. Your story goes in the bracket, the prompt describes the style.

    Here's my story: [STORY, or "the plan we made"]. The art sheets and backgrounds are in inputs/ and the voice or song is in audio/.
Build it in this style: cut-out animation, like paper cut-outs or stickers. Cut each drawing out of the sheets and lay the characters and props over the painted backgrounds. Animate on twos: swap poses with a small springy settle, add a little squash and stretch and follow-through on hair, tails and clothes, and a subtle hand-drawn boil on everything so the cut-outs and backgrounds feel like one layer. Time it to the audio first (word timings for voices, a beat grid for a song). Build any text, menus or screens in code, never over a face. Make a deliberate transition at every scene change. If I don't give you sound, write the sound effects and music in code, and keep them quiet wherever someone is talking.
Show me three stills before the full render.

This workflow works best for styles where characters don't have to move smoothly, like paper cut-out animation or pixel art. For a simple hand-drawn look with no artwork at all, try the Code doodle template.

If you get stuck

Help

Claude only shows me code and doesn't make files

You're in the regular chat. Switch to the Code tab and open your project folder.

It can't find the ZIP

Tell Claude where it is, or move the ZIP into your project folder and say "the kit is in this folder".

It keeps asking permission

Pick Accept edits for this folder. Claude will still ask before installing anything or spending credits.

The text covers the face or the product

Give the timestamp and what should move, for example: "At 0:03 the headline covers her face. Move it to the top third."

The Whisper step fails on my Mac

It usually means Apple's Command Line Tools are missing. Tell Claude: "Run xcode-select --install, I'll click Install, then try Whisper again."

I need frame-exact word timing

For lip sync or word-by-word captions, ElevenLabs' Scribe gives more precise word timestamps than the local Whisper. It needs an ElevenLabs account and API key, so only ask Claude to use it if you have one.

The first video isn't quite right

That's normal, it's a first draft, not a one-click button. Give notes with timestamps, for example "At 0:02 the title comes in too fast". Claude saves every correction to notes/checks.md and reads it before the next render, so the same mistake doesn't come back.

Should I turn on Bypass permissions?

I wouldn't. Bypass lets Claude run any command without asking, and that's where accidents happen. Accept edits is enough for this. Also: keep the project in its own folder, keep a copy of your original images and clips somewhere else, and only add skills or plugins from people you trust.

Does this cost money?

Remotion is free for individuals and small teams (bigger companies need a licence). Claude usage counts toward your plan. OpenArt images use your OpenArt credits, and Claude asks before generating anything paid.
